# Instrumented C++ WC runner

`bmssp-traced.hpp` is a separate modified copy of `include/bmssp-worst-case.hpp` from [lcs147/bmssp](https://github.com/lcs147/bmssp), commit `0a8eb82805bad7f64dfa1b51e17656c9af4c4681`; see `LICENSE` (MIT). The upstream checkout is unchanged. The copied `external/median_of_ninthers.h` and `external/private/median_common.h` carry their original Boost Software License notices; see `BOOST_LICENSE.txt`.

Differences: event hooks at actual recursion entry/exit, pivot selection, distance updates, and returned complete sets; clamp `k` and `t` to at least one for a one-vertex graph; compare unrounded floating-point distance keys. This deliberate numerical correctness patch changes the algorithm implementation; the demo is not pristine upstream. The runner uses `prepare_graph(false)` on all inputs, and therefore preserves original vertex IDs and avoids transformed-node ambiguity. The upstream constant-degree complexity guarantee is not claimed for arbitrary-degree inputs. Upstream collapses parallel edges to their minimum. The unmodified upstream rounds comparison keys to 1e-10. With edges 0?1=4e-11, 0?2=0 and 2?1=0, upstream reports 4e-11 for vertex 1 although the shortest distance is 0. The patched runner reports 0. Floating-point behavior and other algorithmic limitations still require independent validation.

Build with `python bmssp_visualizer/build_native.py`; Python callers can use `ensure_built()`. Invoke `runner.exe INPUT.txt SOURCE trace|plain [SAMPLE_EVERY]`. Input: `n m`, followed by m lines `u v weight`. Nonnegative finite doubles only; weight is restricted to `1e290/n` to protect upstream's numeric sentinel and scaling. Graph IDs are zero-based. Invalid input exits nonzero and prints diagnostics to stderr.

In trace mode, stdout is NDJSON. The process emits `start`, `enter`, `pivots`, `relax`, `complete`, and `exit` from the real computation. Each emitted event is flushed and waits for an input line exactly `next`; EOF or another command terminates early. The start event is always emitted; remaining events are sampled at `SAMPLE_EVERY` (default 1). Sampled runs do not contain every state change. `complete` is an algorithm return set at its specified recursion level, not a blanket assertion that all distances were globally finalized at the instant of a relaxation. The final `native_result` is emitted without a wait, including arrays, sampling counts, execution time excluding control waits, and accumulated control wait. Plain mode emits only this final result and never waits. The execution time includes graph preparation and predecessor reconstruction, excludes file parsing, and controlled timing includes tracing overhead; neither is the original benchmark measurement.

The runner first validates the solver predecessor array against exact binary64 edge equalities and a source-rooted acyclic tree. If this validation fails, it reconstructs a source-rooted tree only from edges satisfying exact binary64 equality; it fails rather than silently outputting a tolerance-only tree if no such tree exists. The result records `predecessor_origin`. Independent verification remains necessary; binary64 equality does not prove real-arithmetic equality. Unreachable distances and predecessor entries are JSON null. No Dijkstra fallback is used.

## Separate no-hook baseline

`ensure_baseline_built()` builds `baseline.exe` using the **original header in the upstream checkout**, with no event hook and no Dijkstra fallback. Run `baseline.exe INPUT.txt SOURCE`; its one JSON line contains `type: baseline_result`, distances and `compute_ms`. The measured interval starts before solver construction, includes insertion of already parsed edges, `prepare_graph(false)`, execution and solver destruction, and excludes parsing, result serialization and path reconstruction. No degree transformation is applied. This is a single no-trace measurement, not the median of a controlled benchmark; it remains subject to normal machine load and upstream numeric behavior, including the near-tie failure above. For `n=1`, upstream has `t=0`, so the wrapper returns the mathematically trivial distance `[0]` without invoking the original algorithm; its timing is not comparable to the solver measurement. Invalid inputs follow the same limits as the instrumented runner.

Regression checks: `python -m unittest discover -s bmssp_visualizer/native -p "test_*.py" -v`. The near-tie test explicitly compares the patched demo with the pristine baseline; tolerance-based verification at 1e-9 can accept the baseline error, so such verification is not exact. Event sampling can omit any intermediate `enter`, `exit`, `relax`, `pivots`, or `complete` event; only `start` and the final result are guaranteed in a completed trace. `complete` reflects the returned set of a specific algorithm call, including its returned bound, not a global promise independent of that call.

## Dijkstra binary heap

`ensure_dijkstra_built()` compiles `dijkstra.cpp` with `-std=c++20 -O2 -DNDEBUG`. Invoke `dijkstra.exe INPUT.txt SOURCE trace|plain [SAMPLE_EVERY]` using the same input and control protocol as the BMSSP runner. The implementation uses a binary min-heap, ignores stale heap entries and relaxes on strict improvement, so zero-weight cycles do not create predecessor cycles. A `complete` event marks a vertex extracted with its current shortest distance; `relax` marks a real improvement. Sampled traces may omit intermediate events. Input edge IDs in native events and `predecessor_edges` are zero-based positions in the input TXT; applications with independently assigned graph IDs must map these positions.

`compute_ms` includes adjacency construction, heap execution, and in trace mode event handling other than ACK waits; it excludes file reading, terminal JSON serialization and `control_wait_ms`. `plain` does not serialize trace events. The BMSSP baseline and Dijkstra measurements perform different implementation-specific setup and are single runs, so they are demos rather than rigorous benchmark conclusions. Input size and weight limits match the BMSSP runner.

## Fidelity fixes and open limits

Optional `count_operations` records BMSSP queue Insert/Pull/BatchPrepend calls and prepend input sizes for a separately profiled run. It defaults to false. Normal UI traces do not add queue events. The v2 benchmark enables it only for its separate profile and excludes those profile times from timing summaries.

The instrumented fork also deduplicates each FindPivots frontier, consistent with Algorithm 1 set semantics, and uses explicit lookup markers for priority-queue upper bounds so that comparator searches do not dereference a default iterator. These changes do not establish full correctness or worst-case complexity. Root propagation versus the final forest, lazy-heap behavior, all batch priority queue invariants and amortized/worst-case selection remain open. `test_batchpq.cpp` exercises selected ordering/duplicate-key cases with debug iterators; it is not a proof. `graph_stats()` reports actual prepared graph sizes and degrees, and the mapping getters expose internal arrays for inspection. The degree-transform branch is not enabled by the demo. Isolated vertices now receive distinct prepared nodes, and nonnegative self-loops are omitted; regression covers a singleton, isolated sources, self-loops, parallel edges, zero edges and mapping. Path recovery and degree transformation remain uncertified in general.
